# Plan: Production Readiness (Issue #15)

## Objectives

Add three production-readiness improvements to the Dugout app:

1. GitHub Actions CI running Playwright smoke tests on every PR and push to main
2. axe-core accessibility audit integrated into `smoke.spec.ts`
3. Critical user journey spec for Announcements, Payments, Schedule, and Auth flows

## Acceptance Criteria

- `.github/workflows/playwright.yml` triggers on PR + push to main, runs `e2e/smoke.spec.ts` on Chromium, uploads report on failure
- `npm install --save-dev @axe-core/playwright` added; accessibility test added to smoke.spec.ts after the "join page loads" test
- `dugout/e2e/journeys.spec.ts` created with 4 journey stubs that skip gracefully when auth credentials are absent

## Key Decisions

- Smoke tests run only `--project=chromium` in CI (fast; mobile projects need real devices or Supabase)
- `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` passed as GitHub secrets so the Vite app boots even when Supabase is unreachable
- axe violations filtered to `critical` and `serious` impact only — minor/moderate violations acceptable at this stage
- Journey stubs use `authTest` from `./fixtures/auth` for the auth-gated flows, and base `test` for the sign-up flow
- Auth journey checks for either `/teams` redirect or an email-confirmation prompt (both are valid sign-up outcomes)

## Implementation Steps

1. `git checkout -b feature/15-production-readiness`
2. `npm install --save-dev @axe-core/playwright` (from `dugout/`)
3. Write `.github/workflows/playwright.yml`
4. Add axe test to `dugout/e2e/smoke.spec.ts`
5. Create `dugout/e2e/journeys.spec.ts`
6. `npm run lint && npm run typecheck` — fix any issues
7. Run `npx playwright test --project=chromium e2e/smoke.spec.ts` locally
8. Commit, push, open PR referencing #15
9. Comment and close issue #15

## Risks

- axe may flag violations on the join page with an invalid team code (content rendered by error state); filtered to critical/serious so this is unlikely to block
- Journey stubs are intentionally lightweight — full assertions require a live Supabase instance and real test data
